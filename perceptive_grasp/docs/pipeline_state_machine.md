# pipeline 状态机

pipeline 使用状态机组织目标检测、三维几何估计、策略选择、底盘辅助和机械臂动作。任务启动后先在当前安全姿态执行 `DETECTING` 和 `PLANNING`。规划器根据目标三维形状和候选可执行性选择顶抓或侧抓，不读取目标类别。

目标超出舒适抓取区时，`PLANNING` 可以在策略锁定前或观察动作完成后进入 `BASE_ALIGNING`。底盘每次停车后都返回 `DETECTING`，重新获取彩色图和深度信息，并关联同一目标实例。目标位置满足要求后，pipeline 锁定策略、进入对应观察位，再次检测并完成工作空间、逆运动学和完整路径验证。

运行阶段发生不可恢复错误时，状态机进入 `RECOVERING`。单次任务回到 home 位；`--loop` 模式在夹爪未持物时回到当前策略对应的观察位。夹爪可能持物时，恢复流程优先放置物体并结束自动循环。

## 1. 状态定义

| 状态 | 作用 |
|------|------|
| `IDLE` | 等待目标命令 |
| `OBSERVING` | 根据已锁定的抓取策略移动到顶抓或侧抓观察姿态 |
| `DETECTING` | 获取 RGB-D 帧并检测目标 |
| `PLANNING` | 估计目标点云和桌面平面，生成顶抓或侧抓候选，规划底盘对齐，并验证工作空间、IK 和完整路径 |
| `BASE_ALIGNING` | 底盘短距离前进、后退或原地转向，动作完成后重新检测 |
| `APPROACHING` | 顶抓移动到预抓取位；侧抓移动到目标上方的安全预抓取位 |
| `GRASPING` | 张开夹爪，下降并进给到抓取位，闭合后检测是否夹住 |
| `LIFTING` | 顶抓向上抬升；侧抓先向上抬升再水平退出 |
| `PLACING` | 移动到放置位并释放 |
| `HOMING` | 放置完成后回到收尾姿态 |
| `RECOVERING` | 任务失败后回到当前运行模式对应的安全恢复姿态 |
| `DONE` | 任务完成 |
| `ERROR` | 任务失败 |

## 2. 执行动作

主循环每 50 ms 调用一次 `SpinOnce()`。机械臂运动、夹爪动作和底盘对齐通过后台 `std::future` 执行。状态机使用 `StartAction()` 启动动作，使用 `PollAction()` 轮询结果，再根据 `GraspResult` 切换状态。

`DETECTING` 根据连续检测框的中心和面积变化判断目标是否静止。目标连续三帧稳定后进入 `PLANNING`。如果候选位置需要底盘调整，pipeline 先执行短距离对齐，再重新检测和规划。目标位置满足要求后，pipeline 进入该策略的观察位。

顶抓使用 `observe_joints`，侧抓使用 `side_ready_joints`。进入侧抓观察位时各关节协调运动，第四关节保持更快的前导进度，避免夹爪触地并推动底盘。观察动作完成后，pipeline 刷新相机数据并重新检测和规划。同一轮任务在策略锁定后只接受该策略的候选，不因单帧深度波动改用另一种抓取方式。

候选通过工作空间、夹爪宽度、关节限制、IK、桌面间隙和完整路径检查后，状态机才进入 `APPROACHING`。顶抓和侧抓的具体规划方法见[抓取方案](grasping_approaches.md)。

取消命令会停止当前任务。夹爪未持物时，机械臂回到观察姿态等待下一条命令；夹爪可能持物时，机械臂回到 home 位并退出程序。若机械臂或夹爪动作正在执行，状态机会等待当前后台动作返回后再执行恢复动作。

抓取成功后，普通指定目标模式在 `HOMING` 阶段回到 home 姿态并退出；语音模式回到观察姿态，等待下一条抓取命令。`--loop` 模式在单轮放置完成后回到本轮策略对应的观察位，随后立即开始下一轮检测，不在轮次之间回到 home。循环模式不区分上一轮目标，视野内满足类别和稳定性要求的目标可以再次被抓取。退出循环时，程序完成安全归位后结束。

语音模式收到 `结束`、`待命`、`休息`、`回家`、`回 home`、`回初始`、`end` 或 `home` 后回到 home 姿态并退出程序。

抓取任务在观察、检测、规划、底盘对齐、接近、夹取、抬升、放置或收尾阶段失败时，状态机自动进入 `RECOVERING`，恢复动作不等待单步确认。

- 单次任务失败后，机械臂回到 home 位。
- `--loop` 模式在夹爪未持物时，单轮失败后回到当前抓取策略对应的观察位，并立即开始下一轮检测。
- 夹爪闭合后发生抬升、放置或执行器错误时，系统按“可能持物”处理，强制回到 home 位并终止自动循环。确认并取下物体后再启动新任务。
- 恢复完成后，pipeline 记录原始失败原因并进入 `ERROR`；恢复动作失败时，最终结果同时记录原始错误和恢复错误。

初始化失败时执行器可能尚未可用，因此不会触发恢复动作。`plan-only` 模式不执行机械臂运动，也不会触发失败回 home。

## 3. 底盘闭环

`BASE_ALIGNING` 可以在策略锁定前介入，也可以在机械臂到达策略观察位并重新规划后介入。策略锁定前，pipeline 根据当前优选候选决定底盘方向；策略锁定后，只使用已锁定策略的定位结果，不在底盘动作后切换顶抓或侧抓。

底盘执行一个短动作并刹车，然后读取动作前后的里程计。有效里程计用于检查底盘是否沿命令方向产生了实际位移或转角；无法读取里程计时，pipeline 使用后续视觉重定位判断动作效果。

经过停车稳定时间后，状态机回到 `DETECTING`。pipeline 获取新帧，并根据类别、图像位置、检测框尺度和形状关联移动前的目标实例，再重新规划。移动前的三维坐标不会复用。已锁定策略因单帧几何波动暂时无法生成候选时，pipeline 保持当前观察姿态和策略并继续检测。

视觉改善量不足、对齐次数耗尽或反复换向时，pipeline 停止底盘修正，并在当前位置继续执行工作空间、IK 和路径检查。只有累计移动达到安全上限、底盘通信失败、相机刷新失败或机械臂安全校验不通过时，任务进入失败终态。

## 4. 状态输出

启用 `--status-stdout` 后，状态机会输出给语音桥使用的事件：

```text
VOICE_STATUS    state=OBSERVING;message=Moving to observe, target: banana;target=banana
VOICE_STATUS    state=DONE;message=Task completed!;reason=success
```

规划成功后保存 `grasp_*.json/png`。json 包含目标三维尺寸、抓取策略、候选位姿和几何耗时；任务结束后保存 `grasp_*_result.json`。

结构化运行日志还会输出 `[Stage N]`、`[Action]` 和 `PIPELINE SUMMARY`，用于查看每个阶段的耗时和最终结果。性能字段说明见[故障诊断](debugging.md#9-分析-pipeline-性能)。

## 5. 失败终态

| 类型 | 示例 |
|------|------|
| 目标不存在 | `Target not found: carrot; candidates: banana(0.89)` |
| 三维几何无效 | `3D grasp geometry failed: ...` |
| 候选不可执行 | `No safe 3D grasp candidate; ...` |
| 底盘对齐失败 | `Mobile base alignment failed: ...` |
| IK 失败 | `Pre-grasp move failed: IK failed` |
| 夹爪空抓 | `Grasp empty; max retries reached` |
| 抓取动作超时 | `Grasp action timeout: timeout`，并附带实际失败动作和诊断信息 |
| 执行器异常 | `motion or device error` |
